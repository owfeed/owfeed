Сборка и релиз

В этом руководстве мы превращаем работающий пакет в подписанные артефакты, которые любой может проверить, и собираем их в CI. Ключей тут два, и работу они делают разную. Прочитайте про них до того, как копировать workflow.

  • Два ключа, один раз: EC подписывает каждый пакет, usign подписывает манифест релиза.
  • Соберите обе линии релизов: 25.12.5 даёт apk, 24.10.8 даёт ipk.
  • Сначала подпись, потом манифест. В обратном порядке манифест ломается.
  • Гоняйте owfeed check на каждом пул-реквесте. Секрет ему не нужен.

Сделать два ключа, один раз

owfeed keygen -o author.pem            # EC prime256v1 — подписывает пакеты
owfeed keygen --usign -o release.key   # usign/ed25519 — подписывает манифест релиза

gh secret set OWFEED_AUTHOR_KEY < author.pem
gh secret set OWFEED_RELEASE_KEY < release.key

git add author.pub.pem release.pub && git commit -m "publish the public halves"
Коммитьте публичные половины. Приватные — никогда. Утёкший подписывающий ключ не отозвать: у apk нет ни CRL, ни срока жизни, ни способа сказать, что ключ мёртв. Генерируйте ключи вне рабочего дерева git. owfeed keygen откажется писать внутрь него без --force. Запишите id ключей, которые он печатает: фид их спросит.

Почему два

КлючПодписываетКто проверяет
EC (author.pem)внутри каждого .apkкто угодно и когда угодно, по вашей публичной половине
usign (release.key)манифест релизафид, один раз, когда забирает релиз

Подпись usign фид проверяет при приёмке, и на этом всё. За пределы CI фида она не выходит.

Подпись EC едет внутри пакета до самого роутера. Поэтому тот, кто фиду не доверяет, всё равно может убедиться: собрали это вы.

Это единственное утверждение о пакете, которое переживает раздачу через фид. Потому фиды её и требуют.

Собрать обе линии релизов

owlab build --release 25.12.5    # apk, для 25.12 и новее
owlab build --release 24.10.8    # ipk, для 24.10 и старее

Обе попадают в dist/<arch>/. Пакет, не зависящий от архитектуры, даёт два каталога:

dist/
├── noarch/my-app-1.0.0-r1.apk
└── all/my-app_1.0.0-r1_all.ipk

Два каталога — это правильно. apk требует noarch и отвергает all. opkg про noarch никогда не слышал.

Собирайте обе линии. На релизе роутеры сидят годами, поэтому, выпуская только под 25.12, вы бросаете всех, кто не обновился.

Соберите пакет перед релизом, даже если sync работал. luci.mk минифицирует JS и CSS, owlab sync — нет. Код, который работает неминифицированным и ломается после минификации, не виден, пока кто-нибудь не соберёт пакет.

Сначала подпись, потом манифест

owfeed sign --key env:OWFEED_AUTHOR_KEY
owfeed release --repo "$GITHUB_REPOSITORY" --tag "$GITHUB_REF_NAME"

Соблюдайте этот порядок. owfeed release записывает размер и sha256 каждого пакета, а подпись дописывает байты в файл. Поменяете местами — манифест будет описывать файлы, которых больше нет.

Что записывает манифест

owfeed release пишет manifest.txt и подписывает его вашим ключом usign. В манифесте:

  • что входит в этот релиз;
  • размер и хеш каждого файла;
  • из какого репозитория и тега он приехал.

Репозиторий записан, потому что подпись доказывает, кто это написал, но никогда — о чём это. Без той строки манифест, взятый из другого вашего релиза, прекрасно прошёл бы проверку как этот.

GitHub Actions

.github/workflows/release.yml

name: release
on:
  push: { tags: ["v*"] }
permissions: { contents: read }
jobs:
  release:
    runs-on: ubuntu-latest
    permissions: { contents: write }
    steps:
      - uses: actions/checkout@v5
      - uses: owfeed/owlab/setup@v0.8.0
      - uses: owfeed/owfeed/setup@v0.5.8

      - run: owlab build --release 25.12.5
      - run: owlab build --release 24.10.8

      - name: Sign the packages, then write the manifest
        env:
          OWFEED_AUTHOR_KEY:  ${{ secrets.OWFEED_AUTHOR_KEY }}
          OWFEED_RELEASE_KEY: ${{ secrets.OWFEED_RELEASE_KEY }}
        run: |
          owfeed sign --key env:OWFEED_AUTHOR_KEY
          owfeed release

      - run: gh release create "${{ github.ref_name }}" --generate-notes
             dist/*/*.apk dist/*/*.ipk dist/manifest.txt*
        env: { GH_TOKEN: ${{ github.token }} }

owfeed release сам читает репозиторий и тег из окружения CI, так что флаги нужны только чтобы их перебить:

CIРепозиторийТег
GitHubGITHUB_REPOSITORYGITHUB_REF_NAME
GitLabCI_PROJECT_PATHCI_COMMIT_TAG
Держите шаги с подписью в джобе, до которой не дотянется пул-реквест. PR из форка запускает вашу сборку, и секрет, доступный оттуда, — это опубликованный секрет. Ограничьте джобу тегом, как выше, или вынесите её отдельно с environment:.

GitLab CI

release:
  rules:
    - if: $CI_COMMIT_TAG
  script:
    - wget -qO- https://github.com/owfeed/owlab/releases/download/v0.8.0/owlab_0.8.0_linux_amd64.tar.gz | tar xz
    - wget -qO owfeed https://github.com/owfeed/owfeed/releases/latest/download/owfeed-linux-amd64
    - chmod +x owfeed && export PATH="$PWD:$PATH"
    - owlab build --release 25.12.5
    - owlab build --release 24.10.8
    - owfeed sign --key env:OWFEED_AUTHOR_KEY
    - owfeed release

Проверить раньше, чем это сделают другие

owfeed check

owfeed check собирает, подписывает, индексирует и прогоняет doctor --require-origin. Для этого он создаёт EC- и usign-ключи на время запуска и потом выбрасывает. Работает во временном каталоге и удаляет его после себя.

Гоняйте его на каждом пул-реквесте. Ему не нужен ни блок signing:, ни секрет, поэтому код форка никогда не выполняется рядом с настоящим ключом.

Отдельный owfeed doctor имеет смысл, только когда у вас есть проиндексированное дерево. Он читает out/ и иначе останавливается со словами run owfeed index first. Репозиторий, который публикует релизы, а не фид, такого каталога не делает.

Находки, на которых спотыкается большинство первых попыток

Находки пронумерованы. Каждая говорит, чем это грозит и что делать.

НаходкаЧто это значит
arch: allapk считает такой пакет неустанавливаемым. Пишите LUCI_PKGARCH:=all и дайте сборке перевести это самой. Так делает и собственная упаковка OpenWrt.
OWF207Файл /etc/config/* кладётся, но не объявлен в conffiles:. При каждом обновлении прошивки sysupgrade молча заменит настройки пользователя вашими дефолтами.
Версия отклоненаПосле ~ apk ждёт хеш коммита, то есть только hex. Пишите 1.0_beta1, а не 1.0~beta.
Переводы не видныLuCI читает скомпилированные .lmo и игнорирует .po. Укажите каталоги в i18n.from:.
